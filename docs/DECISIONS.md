# Decisions

The choices that shaped Readout, and why. The [README](../README.md) has the detail.

| Decision | Why |
|---|---|
| A deliberately tough interviewer | Generous feedback feels good; honest feedback prepares you. Scores are calibrated (5/10 is an acceptable first-round answer, 8+ needs numbers, structure and an insight) and never rounded up. |
| Harsh on the work, never on the person | The evaluator calls out vague thinking and missing numbers, not the reader. |
| One new article per person per day | Keeps each session deliberate and the questions demanding. |
| Suggested threads are Google searches, not links | A model can invent URLs; a search can't point to a page that doesn't exist. |
| A server-side clock for the timed interview | Reloading the page doesn't buy extra time. |
| Glossary lookups are reused | A term looked up once is answered from your own glossary afterwards, with no AI call. |
| No reminders, notifications or streak nudges | Practice should be chosen, not pushed. |
| Moved from a laptop-only app to a hosted one | So other readers could try it; each reader gets a private account behind an invite code. |
